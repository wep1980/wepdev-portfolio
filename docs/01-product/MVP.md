# MVP — WEPDEV Portfolio

## 1. Identificação

- Produto: WEPDEV Portfolio
- Responsável: Waldir Escouto Pereira
- Versão: 1.0
- Estado: Em desenvolvimento
- Idioma principal: Português do Brasil
- Público-alvo: recrutadores, gestores de tecnologia, líderes técnicos e desenvolvedores

## 2. Objetivo

Disponibilizar rapidamente um portfólio profissional público que apresente Waldir Escouto Pereira como Desenvolvedor Java Sênior, demonstrando experiência, conhecimentos técnicos, projetos relevantes e maturidade em Engenharia de Software.

O MVP deve apoiar diretamente a busca por uma nova oportunidade profissional.

## 3. Proposta de valor

O portfólio não será apenas um currículo digital.

Ele deverá demonstrar, por meio do próprio produto e de seus projetos:

- desenvolvimento Java;
- construção de APIs e microsserviços;
- arquitetura de software;
- integração de sistemas;
- testes automatizados;
- DevOps e observabilidade;
- documentação técnica;
- desenvolvimento assistido por Inteligência Artificial.

## 4. Objetivos do MVP

O MVP deverá permitir que um visitante compreenda rapidamente:

1. quem é Waldir;
2. qual é sua especialidade;
3. quais tecnologias domina;
4. onde trabalhou;
5. quais projetos desenvolveu;
6. como acessar seu GitHub e LinkedIn;
7. como entrar em contato;
8. como baixar seu currículo.

## 5. Escopo funcional

### 5.1 Cabeçalho

O cabeçalho deverá apresentar:

- identidade textual WEPDEV;
- link para o início;
- link para a seção Sobre;
- link para a seção Experiência;
- link para a seção Projetos;
- link para a seção Contato.

### 5.2 Apresentação principal

A seção principal deverá apresentar:

- foto profissional;
- nome completo;
- cargo profissional;
- resumo de posicionamento;
- tecnologias principais;
- botão para o currículo;
- botão para o LinkedIn;
- botão para o GitHub;
- botão ou link de contato.

### 5.3 Sobre

A seção Sobre deverá apresentar:

- resumo da trajetória profissional;
- início da carreira como desenvolvedor Java em 2018;
- experiência com aplicações empresariais;
- foco atual em desenvolvimento backend e arquitetura;
- interesse em Inteligência Artificial aplicada à Engenharia de Software.

### 5.4 Tecnologias

A seção deverá destacar, inicialmente:

- Java;
- Spring Boot;
- Quarkus;
- Jakarta EE;
- APIs REST;
- Microsserviços;
- Apache Kafka;
- RabbitMQ;
- Docker;
- Kubernetes;
- PostgreSQL;
- MongoDB;
- Git;
- CI/CD;
- OpenTelemetry;
- Inteligência Artificial aplicada ao desenvolvimento.

A lista poderá ser refinada posteriormente para evitar excesso de informações.

### 5.5 Experiência profissional

A seção deverá apresentar uma linha do tempo resumida contendo:

- empresa;
- cargo;
- período;
- breve descrição das responsabilidades;
- principais tecnologias utilizadas.

Não deverão ser publicados:

- dados internos;
- nomes de clientes confidenciais sem autorização;
- URLs privadas;
- credenciais;
- informações protegidas por contrato;
- detalhes técnicos sensíveis.

### 5.6 Projetos em destaque

O MVP deverá apresentar pelo menos três projetos.

Cada projeto deverá conter:

- nome;
- descrição;
- problema resolvido;
- tecnologias;
- conceitos arquiteturais;
- imagem ou representação visual;
- link para o repositório, quando público;
- estado do projeto.

Os primeiros projetos poderão estar em construção, desde que isso seja informado claramente.

### 5.7 Contato

A seção deverá apresentar:

- LinkedIn;
- GitHub;
- e-mail profissional;
- chamada para contato;
- disponibilidade para novas oportunidades.

### 5.8 Rodapé

O rodapé deverá apresentar:

- nome;
- cargo;
- ano atual;
- links principais;
- tecnologias utilizadas na construção do portfólio.

## 6. Requisitos não funcionais do MVP

O produto deverá:

- funcionar em dispositivos móveis e desktop;
- possuir navegação acessível por teclado;
- utilizar HTML semântico;
- apresentar contraste adequado;
- possuir carregamento rápido;
- gerar build de produção sem erros;
- passar pelo ESLint;
- não expor segredos;
- não gerar custos com APIs de Inteligência Artificial;
- permitir hospedagem no servidor Linux existente;
- possuir documentação versionada;
- utilizar HTTPS no ambiente público.

## 7. Tecnologias do MVP

### Frontend

- Next.js 16;
- React 19;
- TypeScript;
- Tailwind CSS 4;
- App Router;
- Server Components.

### Backend

O backend não é obrigatório para a primeira publicação do portfólio.

Quando introduzido, utilizará inicialmente:

- Java 21;
- Spring Boot;
- Maven;
- PostgreSQL;
- OpenAPI;
- testes automatizados.

### Infraestrutura

- GitHub;
- Docker;
- Nginx;
- servidor Ubuntu;
- domínio já existente;
- GitHub Actions em etapa posterior.

## 8. Conteúdo inicialmente local

Para acelerar a publicação, os dados da primeira versão poderão permanecer em arquivos locais do frontend.

Exemplos:

- experiências;
- tecnologias;
- projetos;
- links;
- informações profissionais.

A integração com backend será realizada posteriormente, sem bloquear a publicação inicial.

## 9. Fora do escopo do MVP

Não fazem parte da primeira versão:

- painel administrativo;
- autenticação;
- cadastro de usuários;
- comentários;
- newsletter;
- banco de dados obrigatório;
- integração paga com OpenAI;
- chatbot público;
- RAG;
- sistema completo de blog;
- internacionalização;
- tema claro;
- animações complexas;
- métricas avançadas;
- integração automática com LinkedIn;
- publicação automática de conteúdo em redes sociais.

Esses itens poderão ser avaliados para versões futuras.

## 10. Restrições

- A primeira versão deve ser entregue rapidamente.
- Nenhuma funcionalidade deve gerar custo recorrente sem aprovação.
- Informações confidenciais de empresas anteriores não podem ser publicadas.
- O projeto deve priorizar simplicidade e qualidade.
- Novas ideias que não sejam essenciais devem ser direcionadas ao roadmap.

## 11. Critérios de aceite

O MVP será considerado pronto quando:

- a página pública estiver acessível pelo domínio;
- as principais seções estiverem implementadas;
- os links de GitHub e LinkedIn funcionarem;
- o currículo puder ser acessado ou baixado;
- pelo menos três projetos estiverem apresentados;
- a página estiver responsiva;
- o ESLint passar sem erros;
- o build de produção for concluído;
- não existirem informações sensíveis;
- a documentação principal estiver atualizada.

## 12. Indicadores de sucesso

O MVP deverá facilitar:

- inclusão do link no LinkedIn;
- inclusão do link no currículo;
- envio do portfólio para recrutadores;
- apresentação dos projetos em entrevistas;
- demonstração pública da evolução técnica.

## 13. Evoluções posteriores

Após a publicação do MVP, poderão ser adicionados:

- backend Java;
- banco de dados;
- estudos de caso detalhados;
- blog técnico;
- Laboratório de IA;
- comparação entre OpenAI e Ollama;
- projetos com RAG;
- observabilidade;
- testes de interface;
- métricas de acesso;
- versão em inglês;
- automação de deploy;
- painel de administração.
