# Project Charter

## 1. Propósito

A WEPDEV Portfolio é uma plataforma web desenvolvida para representar a experiência profissional, as competências técnicas e a capacidade de engenharia de software de Waldir Escouto Pereira.

O projeto possui dois objetivos principais:

- Servir como portfólio profissional para processos seletivos.
- Demonstrar, através de código, documentação e arquitetura, a forma como soluções de software são projetadas e desenvolvidas.

O projeto será totalmente público e desenvolvido utilizando práticas modernas de Engenharia de Software.

---

## 2. Objetivos

### Objetivo Principal

Disponibilizar um portfólio profissional moderno que aumente significativamente as oportunidades de recolocação como Desenvolvedor Java Sênior.

### Objetivos Secundários

- Demonstrar domínio em Java e Spring Boot.
- Demonstrar boas práticas de arquitetura.
- Construir um projeto Open Source de alta qualidade.
- Servir como laboratório para evolução contínua.

---

## 3. Escopo do MVP

A primeira versão conterá exclusivamente:

- Página Inicial
- Sobre
- Experiência Profissional
- Projetos
- Contato
- Backend REST
- Deploy em servidor Ubuntu

---

## 4. Fora do Escopo do MVP

As funcionalidades abaixo estão planejadas para versões futuras:

- Blog
- Laboratório de IA
- Dashboard
- Área Administrativa
- Login
- OpenAI
- Ollama
- Kubernetes
- Redis
- GitHub API
- Analytics

---

## 5. Público-Alvo

A plataforma é destinada principalmente a:

- Recrutadores
- Tech Leads
- Arquitetos de Software
- Desenvolvedores
- Empresas de Tecnologia

---

## 6. Critérios de Sucesso

O projeto será considerado bem-sucedido quando atender aos seguintes critérios:

- Portfólio publicado em domínio próprio.
- Código-fonte público e documentado.
- Arquitetura documentada.
- README profissional.
- Projeto executável localmente através do Docker.
- Demonstração clara das competências técnicas do autor.

---

## 7. Premissas

- Todo o código será público.
- O projeto utilizará tecnologias amplamente adotadas pelo mercado.
- A documentação fará parte da entrega.
- O desenvolvimento será incremental.

---

## 8. Restrições

- O projeto deverá minimizar custos de infraestrutura.
- Nenhuma chave de API será exposta publicamente.
- Funcionalidades que dependam de serviços pagos serão opcionais.
- O foco inicial será exclusivamente no MVP.
